Принципы построения архитектуры
3.1. Архитектурные принципы
Микросервисная архитектура:
Сервисы RES являются частью платформы UCD (Unified Customer Data)
Каждый сервис отвечает за свою предметную область (Single Responsibility)
Независимое развертывание и масштабирование сервисов
API-First:
Все функции доступны через REST API
Использование OpenAPI/Swagger для документирования
Версионирование API (v1, v2, etc.)
Событийная интеграция (Event-Driven):
Использование JMS (Apache ActiveMQ Artemis) для асинхронной передачи событий
Публикация событий об изменениях данных (создание, обновление, удаление)
Подписка на события от других сервисов
Stateless:
Сервисы не хранят состояние между запросами
Все данные хранятся в базах данных или кэше
Database per Service:
Изолированная схема БД для каждого сервиса
PostgreSQL 13+ для большинства сервисов
Oracle 19c для некоторых сервисов (ed-market-info-service, ucd-agreements-facade)
Централизованная аутентификация:
Keycloak OAuth2/OIDC для всех сервисов платформы
Валидация токенов через Keycloak
Ролевая модель доступа
Observability:
Полная наблюдаемость через метрики Prometheus
Распределенная трассировка (Spring Cloud Sleuth)
Централизованное логирование (ELK Stack)
3.2. Технологические принципы
Java 15/17: Основной язык программирования
Spring Boot 2.x/3.x: Основной фреймворк
Camunda BPM 7.13: Движок бизнес-процессов для BPM сервисов
Spring Security + Keycloak: Аутентификация и авторизация
SpringDoc OpenAPI: Документирование API
PostgreSQL 13/Oracle 19c: Системы хранения данных
Apache ActiveMQ Artemis: Брокер сообщений JMS
Spring Cloud OpenFeign: HTTP клиент для внешних вызовов
MapStruct: Маппинг DTO
Lombok: Утилиты для кода
Maven 3.x: Система сборки
Docker/Kubernetes: Контейнеризация и оркестрация
3.3. Стандарты и регламенты
Стандарт Java-разработки МОEX
REST API Guidelines МОEX
Политика информационной безопасности
