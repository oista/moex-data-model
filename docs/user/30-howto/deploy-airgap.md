# Развернуть на рабочем сервере

Рабочий сервер должен запускать служебный интерфейс, веб-приложение и просмотр модели. Как везти туда программы, когда у сервера нет интернета и нет общего git с машиной разработки, записано в [ADR-058](docs/adr/ADR-058-airgap-image-deploy.md). Решение принято. Образы, файл запуска и скрипты упаковки в репозитории уже есть. Рабочий сервер этим ещё не запущен: архив нужно собрать, перенести и применить.

Зачем два канала. Программы едут образом. Сами модели остаются опубликованным источником в Git (ADR-002) и на рабочем сервере лежат в локальном GitLab, в отдельном репозитории. Сервер держит рабочую копию и читает файлы из неё. Обновление моделей и обновление программ идут независимо.

Где это описано и где лежит сейчас. Решение — [ADR-058](docs/adr/ADR-058-airgap-image-deploy.md). Код программ — в `apps/` и `packages/`. Модели для сервера собираются в отдельный [репозиторий моделей](glossary:models-repo): список путей — `deploy/models-repo/paths.yaml`, команды — `scripts/export_models_repo.py`. В копии на сервере сохраняются `model-assets/` и `generated/`: программы ищут корень по файлу схемы DAMS и по относительным путям в YAML. Для сборки просмотра в той же копии нужен ещё `packages/ontology/publications/`: публикация FIBO лежит там. Схемы и `generated/` в этот репозиторий приходят только [синхронизацией схем](glossary:spec-sync). Реализации туда приходят запросом на слияние, и копия в этом репозитории после выделения остаётся для проверок.

Что сейчас работает. Служебный интерфейс, веб-приложение и сборка просмотра собираются образами `docker/api.Dockerfile` и `docker/web.Dockerfile`. Файл `docker-compose.yml` в корне поднимает их локально: интерфейс читает модели из тома, отдельный шаг забирает репозиторий моделей из GitLab, если задан его адрес. Для проверки на своей машине без GitLab тот же файл запускают вместе с `docker/docker-compose.local.yml`: он подставляет текущий каталог вместо тома моделей. Сборка просмотра при локальном каталоге без адреса GitLab пишет `publication_conformance.json` в этот каталог, как обычная сборка просмотра. Если адрес GitLab задан, просмотр собирается из снимка полученного коммита: файл проверки в живой том не пишется, и рабочую копию после сборки не сбрасывают. Готовый каталог подменяют ссылкой `current`; если сборка не удалась, остаётся прежняя ссылка. Пока коммит моделей и версия образа те же, сборку пропускают. Пока копия моделей не совпала с контрактами образа, служебный интерфейс отвечает 503; адреса проверки жизни и готовности при этом открыты. Веб-приложение спрашивает имя и пароль, если рядом с файлом запуска лежит `auth/htpasswd`; имя из этого файла nginx передаёт служебному интерфейсу. Без файла и с режимом доверенного заголовка контейнер веб-приложения не стартует. Адаптер Git умеет локальную копию, GitHub и локальный GitLab. Упаковка программ лежит в `scripts/pack-docker-images.ps1`. Полную поставку собирает цель `make pack-full`: архив образов, контрольная сумма и описание состава появляются в `reports/docker/`. Пакет для контура собирает `make pack-contour`. Ему нужен номер последней полной поставки в переменной `PARENT_TAG`. Если отпечаток зависимостей совпал, в пакете поставка поверх, иначе полная поставка. На сервере пакет распаковывают и применяют сценарием `apply-contour.sh` из того же архива: он загружает образы или собирает их поверх уже загруженной полной поставки и записывает `MODEL_TAG`. Секреты в эти архивы не входят.

Термины нужны, чтобы отличать три архива и правило выбора между ними. Первый запуск и любая смена того, из чего собран образ, — это [полная поставка](glossary:full-pack). Очередная правка только кода программ, когда основа на сервере уже подходит, — это [поставка поверх](glossary:overlay-pack). На флешку или общую папку кладут один архив со всем, чем поставку применяют, — [пакет для контура](glossary:contour-drop). Какой из двух первых архивов собирать, решает [отпечаток зависимостей](glossary:deps-fingerprint).

Порядок проекта в локальном GitLab, токены и откат моделей — [Модели в локальном GitLab](gitlab-models.md).

Где прочитать решение: [ADR-058](docs/adr/ADR-058-airgap-image-deploy.md), [ADR-002](docs/adr/ADR-002-git-published-source.md).
