# Развернуть на рабочем сервере

Рабочий сервер должен запускать служебный интерфейс, веб-приложение и просмотр модели. Как везти туда программы, когда у сервера нет интернета и нет общего git с машиной разработки, записано в [ADR-058](docs/adr/ADR-058-airgap-image-deploy.md). Статус решения — Proposed: оно записано, но не принято. Образов, скриптов упаковки и связи с GitLab в репозитории нет, и по этому тексту нельзя считать, что сервер уже так устроен.

Зачем два канала. Программы едут образом. Сами модели остаются опубликованным источником в Git (ADR-002) и на рабочем сервере лежат в локальном GitLab, в отдельном репозитории. Сервер держит рабочую копию и читает файлы из неё. Обновление моделей и обновление программ идут независимо.

Где это описано и где лежит сейчас. Решение — [ADR-058](docs/adr/ADR-058-airgap-image-deploy.md). Код программ — в `apps/` и `packages/`. Модели сейчас лежат в этом же репозитории, в `model-assets/`. Отдельного репозитория моделей ещё нет. Когда копия на сервере появится, в ней сохранятся каталоги `model-assets/` и `generated/`: программы ищут корень по файлу схемы DAMS и по относительным путям в YAML.

Что сейчас работает. Служебный интерфейс и веб-приложение запускают из этого репозитория, без образа. Адаптер Git умеет локальную копию и GitHub. Поставки на закрытый сервер нет.

Термины нужны, чтобы отличать три архива и правило выбора между ними. Первый запуск и любая смена того, из чего собран образ, — это [полная поставка](glossary:full-pack). Очередная правка только кода программ, когда основа на сервере уже подходит, — это [поставка поверх](glossary:overlay-pack). На флешку или общую папку кладут один архив со всем, чем поставку применяют, — [пакет для контура](glossary:contour-drop). Какой из двух первых архивов собирать, решает [отпечаток зависимостей](glossary:deps-fingerprint).

Где прочитать решение: [ADR-058](docs/adr/ADR-058-airgap-image-deploy.md), [ADR-002](docs/adr/ADR-002-git-published-source.md).
