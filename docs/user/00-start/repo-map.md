# Карта репозитория

Правьте модели в `model-assets/`. Спецификация DAMS лежит в `model-assets/specifications/moex-dams/0.1/`. Реализации — в `model-assets/implementations/`: общая модель предприятия в `enterprise/`, модели решений в `solutions/` (пример — `solutions/mdm/`). Какие документы входят в проверку, записано в `model-assets/implementations/manifest.yaml`.

Код, который читает и проверяет модели, лежит в `packages/`. Три каталога, без которых не собрать картину: `standard-linkml` читает YAML, `specification-dams` проверяет правила DAMS, `repository-loader` собирает состав по описи. Рядом лежат и другие каталоги того же рода: общие типы ролей (`modeling-kernel`), сборка просмотра (`publication`), внешние онтологии, мост к приложению схем и чтение Git. Как устроены модули внутри этих каталогов, здесь не разобрано: отдельной главы про это ещё нет.

Команды и просмотр — в `apps/`: программа `moex-model` в `apps/cli/`, просмотр публикаций в `apps/viewer/`, служебный интерфейс в `apps/api/`, отдельное веб-приложение в `apps/web/` и отдельное приложение схем `apps/drawdb/`. Скрипты общей проверки и сборки — в `scripts/`, точка входа `scripts/check_all.py` (то же, что `make check`).

Каталог `generated/` руками не правят. Туда сборка кладёт производные файлы: их можно выкинуть и получить снова из `model-assets/`.

Решения о том, как устроен продукт, лежат в `docs/adr/`. Длинное описание архитектуры — в `docs/architecture/`. Текст, который вы читаете, — в `docs/user/`. Заметки о переносе в `docs/migration/` текущим состоянием продукта не являются.
