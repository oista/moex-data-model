# ADR-059: Просмотр в рабочем приложении

**Date:** 2026-11-09  
**Status:** Accepted  
**Normative parent:** [MODELING_ARCHITECTURE.md](../architecture/MODELING_ARCHITECTURE.md)  
**Related:** [ADR-015](ADR-015-viewer-ui-atlas.md), [ADR-058](ADR-058-airgap-image-deploy.md)

## Context

Рабочее приложение (`apps/web`) — оболочка со своим меню. Просмотр публикаций — отдельная статическая страница. [ADR-015](ADR-015-viewer-ui-atlas.md) фиксирует её как один автономный HTML, а не как отдельную информационную систему и не как разметку оболочки.

[ADR-058](ADR-058-airgap-image-deploy.md) разделяет два канала. D1: программы едут образом, файлов моделей в образе нет. D4: на сервере шаг синхронизации делает `git fetch` и быструю перемотку из локального GitLab, затем собирает статический просмотр из этой копии. Правка модели с сервера идёт запросом на слияние, не записью в рабочую копию.

Сейчас шаг синхронизации собирает просмотр на каждом интервале прямо в живой каталог и после сборки делает `git reset --hard` и `git clean` в томе моделей. Сборка пишет файлы не атомарно. Пока идёт запись, nginx может отдать недописанный HTML. Сброс рабочей копии пересекается с чтением того же тома служебным интерфейсом.

## Decision

### D1. Пункт меню и встроенная страница

В боковом меню рабочего приложения, после пункта Models, появляется пункт **Viewer**. Маршрут оболочки не называется `/viewer`: этот путь уже занимает nginx и отдаёт собранный просмотр.

Страница пункта оставляет меню оболочки на месте и открывает собранный просмотр во встроенном окне (`iframe`) на высоту основной области. Рядом — ссылка открыть тот же адрес в новой вкладке. Отдельной вёрстки спецификаций, правил, стандартов и реализаций в оболочке нет: показывается страница, которую собирает `apps/viewer`.

### D2. Только чтение

На рабочем сервере просмотр не редактирует модель. `moex-viewer serve` в этой поставке не запускается: он слушает только `127.0.0.1` и пишет в рабочую копию мимо запроса на слияние. Это противоречит ADR-058 D4.

### D3. Источник — репозиторий моделей в локальном GitLab

Содержимое пункта берётся из репозитория моделей на GitLab того же сервера, как требуют ADR-058 D1 и D4. Разовая копия по scp источником не является. Обновление программ не подменяет модели, обновление моделей не требует нового образа.

Пока адрес репозитория не задан, пункт не показывает пустое окно: страница оболочки говорит, что просмотр ещё не собран.

### D4. Пересборка по смене коммита

Шаг синхронизации по-прежнему забирает ревизию с интервалом. Нижняя граница интервала в скрипте — 5 секунд. Интервал по умолчанию — 60 секунд: задержка «как в реальном времени» не больше этого интервала после слияния в GitLab.

Сборка запускается, когда после успешного fetch сменился коммит моделей или сменилась версия образа программ. Версия образа — метка `moexmodel.git_sha` (в процессе это `MOEX_IMAGE_GIT_SHA`). Если метки нет, берётся хеш `generated/manifests/moex-dams-contracts.json` из образа. Совпало с прошлой успешной сборкой — сборку пропускают.

Если сборка длится дольше интервала, интервал не уменьшают. Следующий цикл начинается только после того, как текущая сборка закончилась.

### D5. Атомарная публикация

Для режима с адресом GitLab сборка идёт из снимка `git archive` полученного коммита, не из живого тома. Файл `publication_conformance.json` остаётся во временном каталоге. `git reset --hard` и `git clean` в этом режиме не выполняются: гонки с служебным интерфейсом нет.

Для локального bind-mount без адреса GitLab источник сборки по-прежнему каталог моделей.

Результат пишется в новый каталог релиза. Затем ссылка `current` переключается одной операцией (`ln` во временное имя и `mv -T` на `current`). Неудачная сборка не трогает прежнюю ссылку. Хранятся два последних релиза. nginx отдаёт `/viewer/` из `current`. В релизе лежит `build-info.json`: коммит, время, версия образа, длительность, признак успеха. Его читает страница пункта меню.

## Рассмотренные альтернативы

**1. `moex-viewer serve` в рабочей поставке.**  
Слушает только локальный адрес и пишет мимо запроса на слияние. Отклонено (D2, ADR-058 D4).

**2. Просмотр внутри образа программ.**  
Правка модели стала бы новой поставкой программ, а на сервер попал бы снимок с машины сборки, а не ревизия GitLab. Отклонено (ADR-058 D1).

**3. Своя страница оболочки вместо встроенного окна.**  
Пришлось бы второй раз собрать интерфейс ADR-015 внутри `apps/web` и дальше вести два клиентских слоя. Отклонено. Оболочка показывает уже собранную автономную страницу.

## Последствия

- Меню рабочего приложения и просмотр обновляются разными каналами: оболочка — с образом программ, содержимое — со сборкой из GitLab.
- Во время сборки `/viewer/` продолжает отдавать предыдущий целый релиз.
- Сбой сборки или остановка служебного интерфейса не очищает опубликованный просмотр.
- Расхождение схемы DAMS между образом и репозиторием моделей по-прежнему останавливает приём запросов интерфейса (ADR-058 D4.3). Сборка просмотра при этом может пройти. Страница пункта показывает состояние сборки, а не прячет его.
- Кнопка «обновить сейчас» этим решением не требуется. Её можно добавить отдельно, если интервала недостаточно.

Одна тема на шаг. Схемы и `generated/` серия не меняет.
