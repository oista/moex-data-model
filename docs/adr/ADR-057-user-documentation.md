# ADR-057: Пользовательская документация как описание текущего состояния

**Date:** 2026-11-02  
**Status:** Accepted  
**Normative parent:** [MODELING_ARCHITECTURE.md](../architecture/MODELING_ARCHITECTURE.md)  
**Related:** [ADR-015](ADR-015-viewer-ui-atlas.md), [ADR-016](ADR-016-publication-section-kinds-and-profiles.md), [ADR-028](ADR-028-package-documentation-section.md)  
**Plan:** [.cursor/plans/moex-data-model_user_documentation_c2ba011f.plan.md](../../.cursor/plans/moex-data-model_user_documentation_c2ba011f.plan.md)

## Context

Картину «что такое продукт сейчас» приходится собирать из нескольких мест:
нормативного [MODELING_ARCHITECTURE.md](../architecture/MODELING_ARCHITECTURE.md),
указателя ADR, матрицы ограничений, планов реализации, заметок о миграции и
сессионных планов. Часть этих текстов уже расходится с репозиторием. Нужна
одна понятная точка входа для архитектора и для агентов: что продукт умеет,
как устроен и что актуально, без воды и без новых норм.

## Decision

### D1. Иерархия истины

`docs/user` описывает продукт **как он есть** и **не вводит норм**.

При расхождении правы, по порядку:

1. Accepted ADR;
2. [MODELING_ARCHITECTURE.md](../architecture/MODELING_ARCHITECTURE.md) и схемы;
3. код и `model-assets/`.

Страницу в `docs/user` исправляют. Черновики, `docs/migration/` и
`.cursor/plans/` текущим состоянием продукта не являются.

### D2. Правило языка

Обязательно для каждой страницы и для каждой карточки глоссария.

- **Без жаргона.** Сначала обычное русское объяснение. Имя из репозитория —
  только если без него нельзя найти место в коде, и сразу с пояснением.
- **Минимум терминов.** На странице оставляют только термины, без которых
  мысль не собрать. Термин, который встретился один раз и никуда не ведёт,
  выбрасывают.
- **Термин на странице.** На странице сказано, зачем термин нужен здесь, и
  стоит ссылка `[слово](glossary:id)`. Определение живёт только в карточке
  глоссария. Второй формулировки того же термина не пишут.
- **Понятность важнее точной, но тёмной формулировки.** Предложение должно
  быть понятно архитектору, который открыл репозиторий впервые. Если фразу
  приходится перечитывать, её переписывают.
- **Грамотность.** Правильный русский язык, законченные предложения, без
  кальки с английского и без обрубленных списков вместо текста.
- **Простота.** Одна страница отвечает на четыре вопроса: что это, зачем,
  где лежит, что сейчас работает. Подробности не пересказывают — дают
  ссылку на ADR или код.

### D3. Файлы

| Путь | Назначение |
|---|---|
| `docs/user/user-docs.yaml` | манифест модуля документации |
| `docs/user/toc.yaml` | дерево глав и страниц |
| `docs/user/glossary.yaml` | термины |
| `docs/user/NN-глава/*.md` | страницы |
| `docs/user/90-reference/descriptions.yaml` | русские фразы к командам, целям Makefile и шагам общей проверки |
| `docs/user/index.html` | собранный HTML; коммитится и совпадает со сборкой |

Имя манифеста **не** `publish.yaml`: основной просмотрщик публикаций его не
подхватывает, и на него не распространяется ProfileSpec из ADR-016.

Оболочка HTML совпадает с Publication Viewer (дерево слева, стили, поиск):
переиспользуются шаблоны и стили `apps/viewer`, меняется только наполнение.

### D4. Шапка страницы

Черновик, пока человек не сверил текст:

```yaml
---
id: what-is-this
sources:
  - docs/architecture/MODELING_ARCHITECTURE.md
draft: true
---
```

После сверки человеком `draft` снимают и ставят дату:

```yaml
verified_at: 2026-11-02
```

- `id` — стабильный идентификатор страницы;
- `sources` — пути от корня репозитория, на которых держится текст. Каждый ADR,
  который назван в тексте, входит в этот список. Ссылка в хвосте страницы не
  заменяет абзац и покрытием темы не считается;
- `draft: true` — человек ещё не сверил страницу. Вместе с `verified_at` поле
  не ставят;
- `verified_at` — дата сверки человеком. Её нет, пока стоит `draft`.

Заголовок страницы живёт в `toc.yaml`, не в шапке.

### D5. Оглавление

```yaml
chapters:
  - id: start
    title: Начало
    pages:
      - id: what-is-this
        path: 00-start/what-is-this.md
        title: Что это за продукт
not_covered:
  - adr: ADR-003
    reason: "ещё не принято, к текущему продукту не относится"
```

Страница, которую собирают из репозитория, вместо `path` указывает вид:

```yaml
      - id: adr-status
        generated: adr-status
        title: Статусы решений
```

Виды: `adr-status` (шапки `docs/adr/ADR-*.md`), `cli-commands` (команды
`moex-model` и просмотрщика), `make-targets` (цели Makefile), `check-steps`
(шаги `scripts/check_all.py`). У такой страницы нет файла, шапки, `draft` и
`sources`: факты берутся из этих файлов. Русская фраза к команде, цели и шагу
лежит в `docs/user/90-reference/descriptions.yaml`. У этого файла тот же
контракт сверки, что у страницы: `draft: true` или `verified_at`, не оба сразу.

`not_covered` — явный список Accepted или иных ADR, которые страницами не
охватываются, с причиной. Без причины запись недействительна. Причина говорит
о продукте («ещё не описано: нет главы про приложения»), а не о номере будущего
PR. Когда глава, которая закрывает причину, написана, запись убирают в том же PR.

Список виден читателю. Сборка кладёт его в главу «Что ещё не рассказано»,
на страницу «Принятые решения без страницы». Отдельный markdown для этого
не заводят: страница собирается из `not_covered`.

### D6. Глоссарий

Список `terms`. У каждого термина:

| Поле | Смысл |
|---|---|
| `id` | стабильный идентификатор |
| `term` | отображаемое имя |
| `short` | одна фраза |
| `explanation` | один абзац |
| `see_also` | связанные `id`; в карточке виден `term`, не сырой `id` |
| `sources` | пути от корня репозитория |
| `draft` | `true`, пока человек не сверил карточку |
| `verified_at` | дата сверки человеком; вместе с `draft: true` не ставят |

### D7. Ссылки на термины

В тексте страницы: `[топология](glossary:topology-ownership)`.

Несуществующий `id` — ошибка сборки.

### D8. Актуальность

Проверка **падает**, если:

- путь из `sources` не существует;
- относительная ссылка или ссылка `glossary:` битая;
- Accepted ADR не упомянут ни на одной обычной странице и не записан в
  `not_covered` с причиной. Собираемая страница (`generated:`) и страница
  «Принятые решения без страницы» покрытием не считаются: номер ADR на них
  тему не закрывает;
- в причине `not_covered` указан номер будущего PR;
- запись `not_covered` не попала на страницу «Принятые решения без страницы»;
- у страницы или карточки глоссария нет ни `draft: true`, ни `verified_at`,
  либо стоят оба сразу;
- у `descriptions.yaml`, когда файл уже есть, нет ни `draft: true`, ни
  `verified_at`, либо стоят оба сразу;
- собрана страница вида `cli-commands`, `make-targets` или `check-steps`, а в
  `descriptions.yaml` нет фразы для команды, цели или шага, фраза пустая, или
  фраза осталась у команды, цели или шага, которых уже нет;
- `docs/user/index.html` не совпадает со свежей сборкой.

Проверка не судит язык страницы и не отвечает на четыре вопроса из D2.
Это обязанность автора, а не механический фильтр.

Предупреждение, не ошибка:

- стоит `draft: true` — человек ещё не сверил текст;
- файл из `sources` менялся в git после `verified_at` (и у страницы, и у
  карточки глоссария);
- в тексте назван ADR, которого нет в `sources` этой страницы или карточки.

Журнала «Что нового» нет. Историю изменений смотрят в git. Статусы решений,
когда глава «Состояние» написана, собираются из шапок ADR, а не копируются
руками.

**Обязанность автора.** В том же PR обновляют затронутую страницу (`sources`,
а после человеческой сверки — `verified_at`) и карточку глоссария, если
страница вводит новое слово. На странице сказано, зачем термин здесь;
формулировка определения живёт в глоссарии. Это делают, если меняется:

- новый ADR, его статус или текст уже принятого ADR;
- схемы, каталог требований или матрица проверок;
- раскладка `apps/`, `packages/` или `model-assets/`;
- нормативные файлы в `docs/architecture/`;
- цели Makefile или шаги общей проверки — и фраза в `descriptions.yaml`;
- команды CLI — и фраза в `descriptions.yaml`;
- шаблоны или стили просмотрщика — тогда же заново собирают
  `docs/user/index.html`.

Сборку `docs/user/index.html` обновляют в том же PR при любом изменении
исходников `docs/user`. Дату `verified_at` пишет человек после сверки.
Черновик агента оставляют с `draft: true` и без даты: сегодняшнее число
сверкой не является.

Cursor-правило для агентов повторяет эту обязанность. Сама обязанность
записана здесь.

### D9. Серия PR

| PR | Тема |
|---|---|
| PR-0 | этот ADR и строка в указателе |
| PR-1 | сборка `docs/user/index.html` и проверка актуальности |
| PR-2 | разделы «Начало», «Ключевые идеи», полный глоссарий |
| PR-3 | «Архитектура», «Как это работает», «Состояние сейчас», «Справочник» |
| PR-4 | правило для агентов и правка корневого README |

Первая серия вводит документацию. Вторая дописывает главы, которых в ней нет.
Статус ADR от номера серии не зависит. Решение принято отдельно, после того
как главы второй серии написаны.

### Вторая серия: недостающие главы

| PR | Тема |
|---|---|
| PR-0 | эта правка: термин на странице, собираемые страницы, `descriptions.yaml`, без журнала |
| PR-1 | правило агента под ту же правку |
| PR-2 | сборка страниц `generated:` |
| PR-3 | «Справочник» |
| PR-4 | «Состояние» |
| PR-5 | «Архитектура» |
| PR-6 | «Как это работает» |
| PR-7 | подчистка уже написанных страниц и предложение принять ADR |

Противоречие в D2 снято. Решение принято отдельным шагом человека, когда
главы второй серии написаны. Агент статус сам не меняет.

## Consequences

- Появляется единая описательная точка входа без второго нормативного слоя.
- Авторские PR, которые меняют ADR, схемы, каталог требований, матрицу проверок,
  раскладку репозитория, нормативные файлы архитектуры, шаги проверки, CLI или
  оболочку просмотрщика, обязаны держать `docs/user` в актуальном состоянии.
- Документация пакетов реализации (ADR-028) остаётся рядом с моделью и не
  заменяет `docs/user`.
- Журнала дат нет: статусы ADR собираются из их шапок, история остаётся в git.
- Собираемые страницы и список ещё не рассказанного не закрывают покрытие
  Accepted ADR.

## Alternatives

| Alternative | Why not |
|---|---|
| Только раздел внутри основного Publication Viewer | Смешивает каталог моделей с описанием продукта; манифест попал бы под ProfileSpec |
| Новый HTML без оболочки viewer | Дублирует дерево, стили и поиск |
| Не коммитить `index.html` | Нет единой открываемой «правды» без локальной сборки |
| Писать нормы прямо в `docs/user` | Создаёт седьмой источник истины, который устареет быстрее ADR |
